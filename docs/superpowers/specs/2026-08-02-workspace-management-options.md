# 工作空间管理 UI 方案草稿

日期：2026-08-02
状态：已定稿（采用方案 1）

## 背景

当前"工作空间"仅体现为 Agent 设置中的全局 `agent.workspace_root`，切换需进入设置弹窗修改路径；会话存储于全局列表，与工作空间无任何关联。用户提出两个痛点：

1. 工作空间的设置/切换管理不方便；
2. 工作空间与会话的关系在界面上没有体现。

经需求澄清，确认"工作空间"定位为**完整工作区**：包含工作目录、独立的 Agent 设置与 MCP 服务器、以及归属该空间的会话历史。

## 方案 1：侧边栏顶部空间切换器（选定）

### 布局

```
┌──────────────┬──────────────────────┐
│ 🐋 chatWhale │  会话标题             │
│ ┌──────────┐ │                      │
│ │ ▾ 项目A   │ │  ← 空间切换器：显示    │
│ │  /path/A │ │    空间名+路径，点击    │
│ └──────────┘ │    弹出空间列表        │
│ [+] 新建对话 │                      │
│ 今天         │                      │
│ ● 会话1 ◻A  │                      │
│ ● 会话2 ◻A  │                      │
│ ...         │                      │
└──────────────┴──────────────────────┘
```

### 要点

- 空间切换器固定在侧边栏顶部（品牌区下方、新建对话按钮上方），显示当前空间名 + 路径，点击弹出空间列表；
- 切换空间后，会话列表立刻过滤为该空间的会话（仍按今天/本周/更早分组），会话项带所属空间颜色标识；
- 新建会话自动归属当前空间；
- 空间管理（新建/复制设置/归档/恢复/彻底删除）集中在切换器的"管理空间"入口；
- 切换器内列表可滚动，空间数量增长不影响侧边栏宽度。

### 优点

- 直接命中两个痛点：切换一步到位，空间与会话关系一目了然；
- 改动集中在侧边栏与会话数据层，主聊天视图基本不变；
- 空间数量多时依然可用（选择器内滚动）。

### 缺点

- 需要新增切换器与管理弹窗两个组件，工作量略大于方案 3；
- 空间身份依赖色点等轻量标识，视觉冲击不如方案 2 的 Tab。

## 方案 2：空间 Tab 化

### 布局

侧边栏会话区顶部放一排空间 Tab（可横向滚动），点 Tab 切换空间，会话列表跟随过滤。

### 要点

- 空间身份最直观，当前空间即高亮 Tab；
- 适合空间数量少（3~5 个）的场景；
- 空间多时 Tab 拥挤，需要横向滚动，可发现性下降；
- 新建空间后 Tab 需要自动插入并保持顺序。

### 优点

- 空间切换的"当前态"最显眼；
- 与"工作空间 = 独立环境"的心智模型贴合。

### 缺点

- 空间数量增长后拥挤，扩展性差；
- 路径等元信息难以在 Tab 上展示，需要额外提示。

## 方案 3：空间分组列表（不隐藏）

### 布局

侧边栏仍展示全部会话，但按空间分组（如"项目A / 项目B"），顶部下拉负责切换"当前工作空间"（影响新建会话与设置作用域）。

### 要点

- 保留全局视野，所有空间会话同屏可见；
- 会话多时列表很长，空间身份不够突出；
- 切换器与分组列表职责重叠，用户可能混淆"当前空间"与"分组"。

### 优点

- 实现成本最低，几乎不改动现有会话列表；
- 不会因切换空间而"丢失"其他空间的会话。

### 缺点

- 未能有效回应"空间与会话关系不明显"的痛点；
- 列表长度失控后反而更难管理。

## 结论

选定**方案 1**：它最直接地回应两个痛点（切换方便 + 空间与会话关系可见），扩展性好，且改动集中在侧边栏与会话数据层。详细设计见 `2026-08-02-workspace-management-design.md`。
